So I'm working on some kind of orchestration system where there's a CRUD endpoint



Okay so here the deal with the task endpoint. It's pretty much exactly like the relay endpoint in that it builds on top of existing queue and prompt behavior and ability to pull in messages from an agents and we're going to lightly update relay to keep track of agent state (or we can just track directly in code of task endpoint?) but yeah it's basically an endpoint that allows the orchestrator to manage its own prompting. what happens when it end turns.
so nothing that happens after the todo_write tool is not mediated by the system and we'll need to come up with some way for user to modify/interact with and cancel different tasks. cancel is pause right now. but that's sort of what we need to work on AFTER we get it working 

so yeah task is an endpoint that's totally backward compatible. doesn't touch prompt or queue code AT ALL except to use. same for relay with possibly some slight modifications just to track state of agent that calls a tool that invokes the relay endpoint for the task endpoint logic

There are two possible statuses for an agent/session after calling prompt tool to relay endpoint Waiting and Replying. And a third state implicit in that state being none. AKA we keep two buckets of waiting sessions and replying sessions and add and remove as needed so we've got a third state of not waiting and not replying. So every session that's not in Waiting or Replying is implicitly in NotWaiting.

And agent can move directly from Replying to Waiting. If an agent calls the tool to send message via relay endpoint then status changes automatically

Anyway there are four cases of end-turn inside the task endpoint

Case A: NotWaiting
- Agent never delegated and did not move task to done
Response on end-turn: Reprompt with task, suggestion to delegate, move to done if done

Case B: Waiting
- Agent has called tool to relay endpoint and is Waiting state
Response on end-turn: Do nothing

Case C: Replying — Not Done
- Agent has not called prompt tool to move back to Waiting. Has not moved ticket to done.
Response on end-turn: Reprompt with instructions to fix/delegate. Move to done if done.

Case D: Replying — Done
- Agent has moved the task to done.
Immediate response from endpoint: call cancel on current turn, dequeue next task in list as message to orchestrating agent
