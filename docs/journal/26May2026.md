# 26 May 2026 — Rich Text Editor is COOKING

## What We Just Did

### Rich Text Editor Fixes (MessageEditor.tsx)

1. **Enter in lists now works** — `SendOnEnter` extension checks if cursor is inside `bulletList`, `orderedList`, `blockquote`, or `codeBlock`. If so, returns `false` to let StarterKit handle list continuation. Press Enter twice to exit list.

2. **Shift+Enter is free** — Not captured by any keyboard shortcut. StarterKit's HardBreak extension handles it (inserts `<br>` inside lists/paragraphs).

3. **`extractContentBlocks` completely rewritten** — Full markdown fidelity:
   - Headings → `# Heading`
   - Bullet lists → `- item`
   - Ordered lists → `1. item`
   - Blockquotes → `> quote`
   - Code blocks → ` ```lang\ncode\n``` `
   - Inline marks: `**bold**`, `*italic*`, `` `code` ``, `[text](url)`, `~~strike~~`

4. **@-mentions embed file content** — New `embedMentionContent()` async helper. On send, reads file contents and creates ACP `resource` blocks (embedded context) instead of `resource_link` (just a URI). Falls back to `resource_link` on read failure.

5. **Markdown paste support** — `looksLikeMarkdown()` heuristic detects block-level patterns (`# `, `- `, `1. `, `> `, `` ``` ``). Uses `marked.parse()` → HTML → ProseMirror DOMParser → TipTap JSON. Pasted markdown becomes rich text.

6. **Editor CSS for rich text** — Added purple-dark themed styles for lists, headings, blockquotes, code blocks, inline code, horizontal rules, bold, italic in `.ProseMirror`.

7. **User message bubbles use chat font** — Removed `font-mono` from `UserMessage`, added `.user-message` class. CSS now applies `var(--theme-chat-font)` to both user and agent messages.

### Markdown Preview Theme Sync (MarkdownPreviewPane.tsx)

- Now uses `useWorkbenchFontSize("chat")` and `useChatFontFamily()` hooks
- Applies `className="chat-messages"` so all chat CSS applies

## What We Need to Do Next

### 1. Chat Panel Resizing

**Current state**: The chat panel is a FlexLayout tabset at weight 25 (right side). FlexLayout splitters ARE draggable but they're 2px wide and nearly invisible. The user wants to resize the chat while using it.

**Approach**: 
- Make the splitter more visible (wider, with hover glow)
- Add a keyboard shortcut to toggle chat between "compact" (e.g. 300px) and "expanded" (e.g. 500px) widths
- Consider a drag handle on the chat tab bar itself

**Implementation notes**:
- FlexLayout supports `Actions.updateNodeAttributes(tabsetId, { width: X })` to set pixel width
- The splitter CSS can be made more prominent:
  ```css
  .flexlayout__splitter { width: 4px; background: var(--theme-accent-10); }
  .flexlayout__splitter:hover { background: var(--theme-accent-25); }
  ```
- Keyboard shortcut: `Ctrl+Shift+L` could cycle chat widths (compact / medium / full)

### 2. Image @ Mentions

**Current state**: The @ suggestion popup shows files and "Selection" context. Images can be pasted/dragged but there's no @-mention path for them.

**Desired behavior**: When typing @, image files (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`) appear in the suggestion popup under an "Images" category. Selecting one inserts an image node (same as paste/drag).

**Implementation plan**:
1. In `MessageEditor.tsx`, when scanning workspace files for @-mentions, also collect image files
2. Add them to `mentionItemsRef` with category "Images" and icon 🖼️
3. In `Mention.extend({ renderHTML })`, detect image mentions and render as `<img>` instead of chip
4. In `extractContentBlocks`, image mentions should produce `image` content blocks (base64 or resource_link)
5. Actually read the image file, base64 encode it, and embed as `image` block on send

**Alternative**: Instead of base64 embedding (which bloats messages), image @-mentions could just be `resource_link` blocks pointing to the file path. The agent can read the file if it needs to analyze it. This is simpler and avoids huge payloads.

### 3. Link Paste with Source Attribution

**Current state**: Pasting a URL just dumps the raw text.

**Desired behavior**: When pasting content from a webpage (rich text), preserve the link and show attribution. Or when copying from chat/agent output, preserve the source context.

**Implementation plan**:
- Extend `handlePaste` to detect HTML with links
- When HTML paste contains `<a>` tags, convert them to ProseMirror link marks
- For plain text URLs, auto-detect `http://` / `https://` patterns and convert to links
- Consider: when copying from chat messages, include metadata about which agent/session produced the content

### 4. Configurable Enter Behavior

**Current state**: Enter sends (unless in list/blockquote/codeBlock). Shift+Enter inserts hard break.

**Desired**: User wants to configure whether Enter sends or inserts newline, and whether Shift+Enter does the opposite.

**Implementation plan**:
- Add `workbench.chat.sendOnEnter: boolean` to settings
- Default: `true` (Enter sends, Shift+Enter = newline)
- When `false`: Enter = newline, Shift+Enter = send
- `SendOnEnter` extension reads setting on initialization

### 5. @ Content Injection (The Big One)

**Current state**: @-mentions create `resource_link` blocks. For file mentions, we now read content and embed as `resource` blocks. But "Selection" and other context types aren't implemented.

**ACP Content spec says**:
- `resource` blocks embed complete file contents (we now do this for files)
- `resource_link` blocks are just references
- For "Selection", we'd need to capture the current editor selection and embed it

**Implementation plan**:
1. "Selection" @-mention: Capture current editor selection text, create `resource` block with that text
2. "Current File" @-mention: Capture the active file's content (or just the visible portion)
3. Extend suggestion popup to show these context options alongside files
4. Consider: @-mentions for URLs (web fetch), terminal output, search results
